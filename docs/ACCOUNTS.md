# 계정 발급과 최초 설정

계정은 L4·L5 관리자가 발급합니다. 모든 등급에서 여러 명을 발급할 수 있으며, 같은 학번의 중복 발급은 금지합니다.

## 발급하기

1. L4 또는 L5 계정으로 로그인하고 최초 설정을 마칩니다.
2. 왼쪽 **회원 관리 → 임시 계정 발급**으로 이동합니다.
3. 학생은 학교에서 확인한 학번·이름·성별을 입력하고 등급을 선택합니다.
4. L5 담당자는 이름과 L5 등급으로 발급합니다. 교직원에게 학생 학번을 만들지 않습니다.
5. L4는 L1~L4를 발급할 수 있고, L5 계정 발급은 L5만 가능합니다.
6. L2는 반장·부반장 직책을 선택합니다. 같은 반의 같은 직책을 중복 배정하지 않습니다.
7. L4에게는 발급 직후 임시 로그인 정보를 한 번 표시합니다. 화면을 떠나기 전에 해당 회원에게만 개별 전달합니다. L5는 **임시 로그인 정보 확인**으로 다시 조회할 수 있습니다.

학번은 학년 1자리·반 2자리·번호 2자리의 5자리입니다. 시스템은 1~3학년·01~30반·01~99번을 지원합니다.

## 임시 아이디와 비밀번호 확인

최초 설정 전에는 L5가 계정 발급 화면에서 임시 아이디·비밀번호를 반복 조회할 수 있습니다. 서버가 AES-GCM으로 암호화해 보관하며 암호화 키는 Supabase 서버 비밀 설정에만 둡니다. 관리자 컴퓨터의 운영용 키 백업도 Git에서 제외합니다.

조회 목록은 15초마다 다시 확인하며 **새로고침**으로 즉시 갱신할 수 있습니다. 다른 탭으로 전환하면 표시를 숨깁니다. 브라우저 저장소에 임시 비밀번호를 저장하지 않습니다. L5의 조회는 활동 기록에 남깁니다.

학생이 아이디·비밀번호 최초 설정을 완료하면 같은 DB 트랜잭션에서 보관된 임시 비밀번호를 삭제하고 목록에서 제외합니다. 이후 L5도 변경된 개인 비밀번호를 확인할 수 없습니다. 이미 복사한 전달 내용이나 별도 파일은 자동 삭제할 수 없으므로 전달한 담당자가 정리합니다.

## 최초 로그인

학교에서 등록한 학번·이름·성별은 본인 확인용으로 표시되고 학생이 직접 바꾸지 못합니다. 정보가 다르면 담당자에게 연락합니다.

임시 아이디는 무작위로 발급하고, 임시 비밀번호는 혼동하기 쉬운 문자를 뺀 영문 소문자·숫자 10자리입니다. 새 아이디는 영문 소문자로 시작하는 4~24자 영문·숫자·밑줄이며 `tmp_`는 임시 계정 전용입니다. 새 비밀번호는 기존과 다른 8~128자입니다. 두 정보를 바꾸기 전에는 커뮤니티를 이용할 수 없습니다.

## 분실 시 재발급과 계정 삭제

회원 · 계정 관리와 등급 관리 화면에서 **학급별 보기**, **등급별 보기**를 함께 선택해 이용자를 찾을 수 있습니다. L4는 회장단과 정보통신부 부장을 함께 표시합니다. 학급이 없는 담당자는 **학급 미지정 · 담당자**로 조회하며, **필터 초기화**로 전체 목록으로 돌아갑니다.

L4·L5는 **회원 관리 → 회원 · 계정 관리**에서 다른 회원의 **계정 삭제**를 선택합니다. **로그인 정보 재발급**은 L5만 가능합니다. 대상 이름을 정확히 입력하고 확인란을 체크해야 실행됩니다. 본인 계정 삭제는 다른 관리자에게, 재발급은 다른 L5에게 요청해야 하며, 마지막으로 이용 가능한 L5를 없애는 작업은 차단합니다.

재발급은 이용 중인 계정에만 가능합니다. 학교에서 본인 요청을 확인한 뒤 처리합니다. 회원의 학번·이름·성별·등급·글·활동은 유지하고, 기존 로그인 정보와 접속 세션을 무효화합니다. 새 임시 정보는 계정 발급 화면의 **임시 로그인 정보 확인**에서 L5만 조회합니다. 회원은 최초 설정을 다시 마쳐야 커뮤니티를 이용할 수 있습니다.

계정 삭제는 Supabase Auth 로그인 계정과 연결된 개인정보·개인 신청 내역을 제거합니다. 게시글·댓글과 학급 제출 기록은 작성자 연결을 제거하고 남깁니다. 삭제 후에는 계정을 복구할 수 없으며, 같은 학생에게 다시 발급하면 새로운 별도 계정입니다. 기존 콘텐츠의 본문에 직접 작성한 이름 등은 자동으로 지우지 않습니다.

서버 장애로 처리를 마치지 못하면 기존 접속을 차단한 상태로 두고 성공으로 표시하지 않습니다. 다른 L5가 같은 계정의 재발급 또는 삭제를 다시 실행할 수 있습니다. 처리 요청과 재발급 완료는 관리자 활동 기록에 남깁니다.

## 운영 설정

SQL 001~016을 순서대로 적용한 후 `account-access`와 `moderate-post`를 배포합니다. 이미 적용한 마이그레이션을 다시 실행하지 않습니다.

`account-access`에는 `TEMP_CREDENTIAL_KEY`를 서버 비밀 설정으로 넣어야 합니다. 값은 암호학적으로 생성한 32바이트의 64자리 hex입니다. `NEXT_PUBLIC_` 변수나 GitHub 저장소에 넣지 않습니다. 저장 중인 비밀번호가 있으면 키를 임의로 교체하지 않습니다.

최초 L5 부트스트랩 CLI는 Git 제외 파일 `.env.admin.local`에 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, 서버와 동일한 `TEMP_CREDENTIAL_KEY`를 설정한 뒤 실행합니다.

```powershell
npm.cmd run provision -- --name 담당자 --role SUPERVISING_TEACHER
```

운영자 CLI는 관리자 권한을 가진 로컬 운영 절차입니다. 일반 웹 사용자는 L4 이상 인증을 거쳐야만 발급할 수 있습니다. 실제 학생 정보·비밀번호를 명령행 인자로 전달하거나 GitHub 파일·이슈·공개 로그에 올리지 않습니다.

## 검증

2026-11-08 실제 Supabase에서 동일 등급 복수 발급, L4 발급·조회 거부, L5 반복 조회, 최초 설정 후 비밀번호 삭제를 검증했습니다. 검증용 가상 계정은 모두 삭제했습니다.

L4는 학생회 회장단과 정보통신부 부장만 해당합니다. 기존 데이터 참조를 보존하기 위해 정보통신부 부장의 내부 역할 코드는 `PR_DIRECTOR`를 유지하며, 화면과 DB 직책명은 정보통신부 부장으로 표시합니다. 계정 발급·목록 조회·삭제는 L4·L5 공통입니다. 재발급과 임시 비밀번호 재조회·L5 계정 발급은 L5 전용입니다.

# 소통해용: 처음 배포하는 사람을 위한 안내

한 번에 모두 할 필요 없습니다. 각 단계가 끝나면 채팅에 완료했다고 알려 주세요. 막히면 버튼 이름이나 오류 문구만 알려 주세요. 비밀번호·비밀키는 보내지 않습니다.

## 우리가 만들고 있는 것

`mpms` 폴더에는 사이트를 만드는 파일이 들어 있습니다. 지금은 내 컴퓨터에서만 확인할 수 있습니다. 다른 사람이 주소를 입력해 접속할 수 있도록 인터넷에 올리는 일을 **배포**라고 합니다.

| 이름 | 쉬운 뜻 | 소통해용에서 하는 일 |
| --- | --- | --- |
| GitHub | 프로그램 파일을 보관하는 온라인 폴더 | 사이트 코드 보관 |
| 저장소 / Repository | GitHub 안에 만든 프로젝트 폴더 | `sotonghaeyong` 폴더 |
| GitHub Pages | 사이트 화면을 인터넷에 보여 주는 서비스 | 학생들이 접속하는 화면 제공 |
| Supabase | 로그인과 자료를 관리하는 서버 | 회원 정보·글·승인 결과 보관 |
| 배포 | 만든 사이트를 인터넷에서 접속 가능하게 올리는 일 | 사이트 주소 만들기 |
| 라이선스 | 다른 사람이 내 코드를 이용할 때 지킬 규칙 | 현재는 별도 허락 없는 이용을 허용하지 않음 |

라이선스는 파일을 숨겨 주는 장치가 아닙니다. 비공개 설정과 실제 데이터 접근 권한도 따로 관리해야 합니다. 외부 라이브러리는 각각의 라이선스를 따릅니다. [GitHub 라이선스 설명](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

## 1단계: GitHub에 빈 프로젝트 폴더 만들기

1. [GitHub](https://github.com/login)에 `leo-0229` 계정으로 로그인합니다.
2. [새 저장소 만들기](https://github.com/new)를 엽니다.
3. **Owner**가 `leo-0229`인지 확인합니다.
4. **Repository name**에 `sotonghaeyong`을 입력합니다.
5. 처음에는 **Private**를 선택합니다. 나만 볼 수 있는 상태로 업로드를 준비하기 위해서입니다.
6. **Add README**, **Add .gitignore**, **Choose a license**는 추가하지 않습니다. 내 컴퓨터에 이미 준비한 파일을 나중에 올립니다.
7. **Create repository**를 누릅니다.
8. 주소가 `https://github.com/leo-0229/sotonghaeyong`인지 확인하고 채팅에 **“저장소 만들었어”**라고 알려 주세요.

이 단계에서는 파일을 직접 올리거나 명령어를 입력할 필요 없습니다. 아직 이 채팅과 GitHub 계정이 연결되지 않았으면, 이후 제가 파일을 올릴 수 있도록 별도 연결이 필요합니다. GitHub 웹사이트에 로그인하는 것과 이 채팅에 GitHub 사용 권한을 주는 것은 각각 다른 절차입니다. [저장소 생성 공식 안내](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)

## 2단계: Supabase 준비

1단계가 끝난 후 안내를 받으며 진행하면 됩니다.

1. [Supabase 관리 화면](https://supabase.com/dashboard)을 엽니다.
2. 계정이 없다면 가입합니다. GitHub 로그인 선택지가 보이면 같은 GitHub 계정으로 로그인할 수 있습니다.
3. 새 프로젝트를 만들 때 이름은 `sotonghaeyong`으로 정합니다.
4. 데이터베이스 비밀번호는 사이트가 관리할 자료를 위한 비밀번호입니다. 비밀번호 관리자에 보관하고 채팅에 보내지 않습니다.
5. 지역과 요금제는 생성 화면을 함께 확인한 뒤 선택합니다. 유료 결제는 진행하지 않습니다.

프로젝트가 만들어지면 회원 정보와 글을 담을 표를 준비합니다. 표를 만드는 SQL과 로그인 처리 코드는 이미 로컬 프로젝트에 있습니다. 연결 도구 사용 권한이 확인되면 제가 적용하며, 웹사이트 로그인만 한 상태라면 함께 별도 연결을 진행합니다.

## 3단계: 사이트 주소 만들기

GitHub에 검사한 코드만 올리고 GitHub Pages 설정을 켭니다. 처음에는 실제 회원 정보가 없는 로그인 준비 화면부터 올립니다.

저장소 이름이 위와 같으면 예상 주소는 `https://leo-0229.github.io/sotonghaeyong/`입니다. **아직 배포되지 않았으므로 지금 열리지 않아도 정상입니다.**

무료 개인 계정에서 GitHub Pages를 사용하려면 공개 저장소가 필요합니다. 그래서 처음 만든 Private 저장소를 유지할지, 검사를 마친 코드만 공개해 Pages를 사용할지 배포 전에 함께 정합니다. 실제 회원 명단·글·비밀번호는 공개 코드에 넣지 않고 Supabase에서 관리합니다. 공개 저장소로 변경하기 전에는 알리지 않고 공개하지 않습니다. [Pages 제공 범위](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)

## 4단계: 로그인과 계정 5개 준비

사이트와 Supabase가 연결되면 임시 계정을 만듭니다. L1 학생, L2 학급 대표, L3 학생회 임원, L4 회장단 또는 홍보부장, L5 담당 교사로 한 명씩입니다.

이름·학번·성별은 확인된 대상자 정보로 등록하며, 공개 GitHub 파일에 넣지 않습니다. 발급받은 사람은 첫 로그인에서 아이디와 비밀번호를 바꿉니다. 모든 글과 댓글은 운영진 승인을 받은 뒤 공개됩니다.

현재 완료한 것은 로컬 사이트 제작과 Git 준비입니다. 실제 GitHub 저장소·Supabase 프로젝트 생성, 인터넷 배포, 실제 계정 발급은 아직 확인되지 않았습니다.

# 소통해용 — 문산중학교 통합 학생 자치 커뮤니티 개발

## 0. 프로젝트 개발 지시

당신은 전문 풀스택 개발자, 데이터베이스 설계자, 웹 보안 엔지니어, UI/UX 디자이너입니다.

지금부터 대한민국 문산중학교 학생회를 위한 웹 기반 통합 학생 자치 플랫폼 **「소통해용」** 을 처음부터 개발하세요.

이 서비스는 학생들이 학교 정보를 확인하고, 자유롭게 의견을 제출하며, 학생회가 각종 학교 업무와 학생 자치활동을 효율적으로 관리하기 위한 웹 플랫폼입니다.

특히 다음 두 가지 성격을 동시에 지녀야 합니다.

1. 네이버 카페처럼 익숙하게 사용할 수 있는 학생 커뮤니티
2. 학생회와 학급 대표가 실제 학교 업무를 처리할 수 있는 운영 시스템

단순한 디자인 시안이 아니라, 실제 로그인, 회원 관리, 게시글 승인, 데이터베이스 저장, 학급별 자료 제출, 관리자 기능이 동작하는 웹 서비스를 목표로 합니다.

모든 UI는 한국어로 제작합니다.

서비스명은 반드시 **소통해용**을 사용하세요.

슬로건은 사용하지 않습니다.

# 1. 핵심 개발 원칙

- 학교 전체 운영 중심
- 네이버 카페형 게시판 UI
- 모바일 및 PC 반응형
- 학생 실명제
- 담당 교사 승인 기반 회원가입
- 학생 게시글 사전 승인
- 학생회 역할에 따른 권한 분리
- 학급 대표 업무 처리
- 전자 건의함
- 학교 행사 및 신청 관리
- 멘토·멘티 프로그램
- 가능한 무료 운영
- 미성년자 개인정보 보호

### 중요한 설계 원칙

**학급별 자유게시판이나 학급별 채팅 서비스를 만들지 마세요.**

이미 학급별 단체 채팅방이 존재하므로 해당 기능은 필요하지 않습니다.

대신 학급 반장과 부반장이 자신의 학급을 대표해서 학교 또는 학생회에 자료를 제출하고, 행사 참가 신청을 하며, 학급별 업무를 처리하는 시스템을 구현하세요.

소통해용은 학급별 커뮤니티가 아니라 **학교 전체의 학생 자치활동을 관리하는 통합 플랫폼**입니다.

# 4. 회원 등급 시스템

정확히 5단계의 역할을 구현합니다.

## LEVEL 1 — 일반 학생

역할 코드: STUDENT

권한:
- 게시판 열람
- 게시글 작성 및 승인 신청
- 댓글 작성(관리 정책에 따른 승인 적용)
- 전자 건의 제출
- 행사 정보 열람
- 학생 개인 신청이 가능한 행사 참여
- 설문조사 응답
- 멘토·멘티 신청
- 자신의 제출 및 신청 현황 확인
- 마이페이지 이용

제한:
- 공식 공지 게시 불가
- 게시글 승인 불가
- 학급 대표 제출 불가
- 운영진 페이지 접근 불가

## LEVEL 2 — 학급 반장 및 부반장

역할 코드: CLASS_OFFICER

세부 직책:
- CLASS_PRESIDENT
- CLASS_VICE_PRESIDENT

LEVEL 1의 기본 기능에 더해 다음 업무 권한을 부여합니다.

### 학급 대표 업무

- 학급을 대표한 학교 행사 참가 신청
- 학급별 자료 제출
- 학생회가 요청한 학급별 설문 제출
- 학급 의견 취합 결과 제출
- 학급별 인원 현황 제출
- 학급별 활동 신청
- 학생회 공지에 따른 학급 대표 응답
- 제출 내역 및 처리 상태 확인
- 제출 마감일 확인
- 제출 내용 수정 요청

### 제한

- 자신의 학급으로만 제출 가능
- 다른 학급을 대신하여 제출 불가
- 학교 전체 공지 작성 불가
- 전체 게시글 승인 불가
- 회원 등급 변경 불가

반장과 부반장은 같은 학급을 대표합니다.

동일한 업무에 대해 중복 제출이 발생하지 않도록 학급 단위 제출 상태를 관리합니다.

학급별 대표 제출 기능은 해당 반장과 부반장 모두 접근할 수 있지만, 제출 내역에 실제 제출자와 수정자를 기록해야 합니다.

## LEVEL 3 — 학생회 임원

역할 코드: COUNCIL_OFFICER

권한:
- 일반 게시글 승인 및 거절
- 학생회 공지 초안 작성
- 학생회 행사 신청 양식 작성 요청
- 학급별 제출 자료 확인
- 담당 업무의 제출 현황 관리
- 미제출 학급 확인
- 전자 건의 접수 및 분류
- 멘토·멘티 신청 관리
- 신고된 게시글 검토
- 학생회 설문조사 관리

제한:
- 회원가입 승인 불가
- 다른 학생의 등급 변경 불가
- 담당하지 않은 민감한 자료 열람 불가
- 보안 설정 변경 불가

## LEVEL 4 — 학생회 회장단 및 대외홍보부 부장

역할 코드:
- COUNCIL_EXECUTIVE
- PR_DIRECTOR

세부 직책:
- 학생회장
- 학생회 부회장
- 대외홍보부 부장

권한:
- 공식 학생회 공지 작성 및 게시
- 학생회 행사 등록 및 관리
- 학급 대표 제출 요청 생성
- 학급별 자료 제출 현황 전체 관리
- 학생회 공약 이행 현황 관리
- 게시판 운영 관리
- 게시글 승인 결과 재검토
- 학생회 설문 관리
- 학생회 임원 업무 배정
- 학생회 운영 통계 확인
- 학급 대표에게 업무 요청 전달
- 제출 자료 검토 및 보완 요청
- 행사 신청 마감 및 결과 확정

제한:
- 회원가입 최종 승인 불가
- LEVEL 5 권한 부여 불가
- 학교에서 보호하는 개인정보에 대한 무제한 접근 불가
- 기술적 보안 설정 변경 불가

## LEVEL 5 — 학생회 담당 교사

역할 코드: SUPERVISING_TEACHER

학교에서 지정한 학생회 담당 교사가 최고 운영 권한을 가집니다.

권한:
- 전체 회원가입 승인 및 거절
- 전체 회원 관리
- LEVEL 1~4 등급 부여 및 변경
- 학생회 임원 및 학급 임원 권한 지정
- 공식 공지 관리
- 게시판 관리
- 학급 대표 업무 관리
- 모든 학생회 행사 관리
- 건의함 총괄 관리
- 멘토·멘티 총괄 관리
- 운영진 권한 회수
- 신고 및 제재 처리
- 사이트 운영 정책 설정
- 관리자 활동 기록 조회
- 학교 운영에 필요한 승인 및 감독

교사도 개인정보에 대해서는 업무상 필요한 범위에서만 접근할 수 있도록 합니다.

인증 비밀키나 사용자 비밀번호는 교사 권한으로도 열람할 수 없습니다.

# 5. 학급 대표 업무 시스템 — 핵심 기능

이 기능은 소통해용의 주요 차별화 기능입니다.

학급별 게시판을 대신해 **학생회와 각 학급 대표가 학교 업무를 주고받는 시스템**을 만듭니다.

## 5.1 기능 이름

메뉴명: 학급 대표 업무

관리자 메뉴명: 학급별 제출 관리

## 5.2 업무 요청 생성

권한을 가진 LEVEL 4 또는 LEVEL 5 운영자가 학급 대표들에게 업무를 요청할 수 있습니다.

권한을 위임받은 LEVEL 3 운영진도 지정된 업무의 요청을 작성하거나 관리할 수 있습니다.

업무 생성 항목:
- 업무 제목
- 설명
- 담당 학생회 부서
- 요청 대상 학년
- 요청 대상 학급
- 제출 시작일
- 제출 마감일
- 제출 형식
- 필수 입력 항목
- 첨부파일 허용 여부
- 추가 안내
- 마감 후 제출 허용 여부

## 5.3 업무 유형

다음 유형을 지원합니다.

### A. 행사 참가 신청

예시:
"학교 체육대회 학급별 참가 신청"

입력 항목:
- 학년
- 반
- 참가 여부
- 참가 인원
- 종목별 참가 명단(학교에서 허용한 경우)
- 비고

### B. 학급 의견 제출

예시:
"학생회에 전달할 학급별 건의사항 제출"

입력 항목:
- 학급
- 건의 분야
- 의견 요약
- 구체적인 내용

### C. 학급별 자료 제출

예시:
"학교 축제 학급별 부스 운영 계획 제출"

입력 항목:
- 학급
- 신청 내용
- 활동 계획
- 필요 물품
- 첨부파일

### D. 학급 대표 설문

예시:
"체육대회 종목 선호도 조사"

학급 대표가 학급 의견을 취합해 대표 응답을 제출합니다.

### E. 일반 업무 요청

운영진이 입력 항목을 자유롭게 구성할 수 있는 사용자 정의 양식을 지원합니다.

초기 버전에서는 텍스트, 숫자, 단일 선택, 복수 선택, 날짜, 파일 첨부 등을 지원합니다.

동적 양식의 유효성 검사는 서버에서 수행합니다.

# 6. 학급 대표 제출 방식

## 업무 진행 흐름

1. 학생회가 업무 요청을 등록합니다.
2. 지정된 학급 대표에게 알림을 전송합니다.
3. 반장 또는 부반장이 업무를 확인합니다.
4. 자신의 학급을 대표하여 내용을 작성합니다.
5. 제출 버튼을 누릅니다.
6. 학생회 운영진이 제출 내역을 확인합니다.
7. 필요하면 보완을 요청합니다.
8. 학급 대표가 수정하여 다시 제출합니다.
9. 학생회가 최종 접수합니다.

## 제출 상태

- NOT_SUBMITTED: 미제출
- DRAFT: 임시 저장
- SUBMITTED: 제출 완료
- REVISION_REQUESTED: 보완 요청
- RESUBMITTED: 재제출
- ACCEPTED: 접수 확정
- CLOSED: 업무 종료

## 중복 제출 방지

하나의 업무 요청에 대해 학급당 기본적으로 하나의 유효한 제출 내역을 유지합니다.

반장이 제출하면 부반장도 제출 현황을 확인할 수 있습니다.

부반장이 수정할 경우 수정자를 기록합니다.

동시 수정 충돌을 방지하기 위해 버전 관리 또는 낙관적 잠금을 적용합니다.

이전 제출 기록은 감사 목적으로 필요한 범위에서 보관하되, 개인정보 보유 정책에 따라 삭제할 수 있도록 합니다.

## 제출 권한

클라이언트가 전달한 학급 ID를 신뢰하지 마세요.

서버에서 사용자 소속 학급과 역할을 검증하세요.

# 14. 회원가입 및 실명 인증

## 기본 정책

학생은 회원가입 신청 후 LEVEL 5 담당 교사의 승인을 받아야 정식 회원이 됩니다.

## 신청 정보
- 이름
- 학년
- 반
- 번호
- 로그인 계정 정보
- 학교가 승인한 학생 확인 방법

학번과 이름만으로 학생 본인임을 확인한 것으로 처리하지 않습니다.

학교에서 공식적으로 지원하는 경우 학교 계정 연동을 검토합니다.

아이톡톡 계정과의 OAuth 연동 가능 여부는 실제 지원 방식을 확인한 후 결정합니다.

학교 계정 비밀번호를 서비스에서 직접 수집하지 마세요.

명찰 사진 등의 민감한 인증 자료를 기본적으로 요구하지 않습니다.

## 회원 상태
- PENDING
- ACTIVE
- REJECTED
- SUSPENDED
- WITHDRAWN

## 역할 부여

가입 승인된 학생은 기본적으로 LEVEL 1입니다.

LEVEL 2~4 역할은 LEVEL 5 담당 교사가 부여합니다.

학급 반장과 부반장에게 LEVEL 2를 부여할 때는 반드시 소속 학급과 직책을 함께 기록합니다.

역할 변경 내역을 저장합니다.

# 21. 반드시 통과해야 할 시나리오

### 회원가입
학생 가입 신청 → 담당 교사 승인 → 정식 회원 활성화

### 학생 게시글
학생 글 작성 → 학생회 임원 검토 → 승인 후 공개

### 학급 대표 제출
학생회가 전 학급에 행사 신청 요청 → 해당 반장 또는 부반장이 자기 반 신청서 제출 → 학생회에서 학급별 제출 현황 확인

### 중복 제출 방지
반장이 제출한 업무를 부반장이 확인 → 기존 제출 건을 수정할 수 있으나 중복 제출 건은 발생하지 않음

### 권한 제한
일반 학생이 학급 대표 업무 제출 API 호출 → 거부

다른 반의 반장이 타 학급 제출 API 호출 → 거부

LEVEL 3 임원이 교사 전용 회원 승인 API 호출 → 거부

### 보완 요청
운영진이 제출 내역 보완 요청 → 해당 반장과 부반장에게 알림 → 수정 제출 → 운영진 최종 접수

### 건의함
학생이 비공개 건의 제출 → 배정된 담당자가 처리 → 작성자에게 결과 제공

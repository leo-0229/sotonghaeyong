현재 정책은 이 문서가 이전 기획·초기 배포 안내보다 우선합니다.

## 게시판과 글 수정

첫 화면은 전체 글 목록입니다. 작성자, 한국 시각의 작성 일시, 조회수, 하트를 표시하며 본문에서 작성·수정 시각을 구분합니다. 학교 행사도 목록형으로 제공합니다. 왼쪽은 학교 소식 세 항목을 기본으로 펼치고 나머지는 접히는 메뉴로 정리했습니다.

게시판별 말머리를 선택합니다. 분실물은 **찾아가용 / 찾아용 / 찾았어용**, 질문은 **궁금해용 / 해결됐어용**입니다. 본인 글의 제목·내용·게시판·말머리를 수정할 수 있고, 원래 작성 시각과 수정 전 이력을 남깁니다. 운영진이 숨긴 글은 작성자가 다시 공개할 수 없습니다.

글과 댓글에는 계정당 하트 한 개를 누르거나 취소할 수 있습니다. 다른 회원에게 누른 사람의 계정 목록을 공개하지 않습니다. 댓글 아래 한 단계의 답글을 작성할 수 있습니다.

## 내용 검사와 자동 승인

규칙 검사에 걸리지 않고 AI가 명확히 안전하다고 판정한 경우만 자동 공개합니다. 욕설·혐오·성적 표현·외부 링크·전화번호·불확실한 문맥은 검토 대기로 처리합니다. AI 미연결·오류도 검토 대기입니다. 수정한 글, 댓글, 공개 건의와 답변에도 같은 원칙을 적용합니다. 자신의 대기 글을 직접 수동 승인할 수 없습니다.

현재 AI API 키는 발급하지 않은 상태이므로 실제 운영은 **검토 대기 → 운영진 승인**으로 동작합니다. 서버의 `OPENAI_API_KEY`, `OPENAI_MODEL`을 연결하면 준비된 자동 승인 경로가 작동합니다. 비밀 설정은 브라우저 변수·소스·GitHub 저장소에 넣지 않습니다.

띄어쓰기·숫자·기호·보이지 않는 문자·한글 자모 분리·영문 자판 입력을 정규화해 알려진 표현을 비교합니다. 웃음·울음·짧은 초성 표현은 폭넓게 허용합니다. 사전과 AI가 모든 신조어·문맥을 완벽히 판단하지 못하므로 운영진 검토와 신고를 유지합니다. 일반적인 성적 지향·정체성 자체를 욕설로 단정하지 않습니다. 교사명 검사와 명단 입력은 비활성화했습니다.

## 학생회 개인 채널

로그인한 회원마다 개인 대화방을 만들고 본인과 학생회 임원(L3·L4)만 읽고 답할 수 있습니다. 다른 학생은 대화방 ID를 알아도 접근할 수 없습니다. L5는 학생회 역할에 포함하지 않아 다른 회원의 채널을 일반 화면에서 읽지 못합니다. 메시지는 서버에 보관하며 전송 빈도를 제한합니다.

행사 신청·취소, 멘토링 신청·매칭, 건의 접수는 해당 개인 채널에 안내를 남깁니다. 알림에서 해당 대화방으로 이동합니다. 화면은 메시지를 주기적으로 갱신하며 이전 대화를 추가로 불러올 수 있습니다.

## 멘토·멘티 연락처

동성 1:1 학교생활 멘토링을 유지하고 활동 시간 입력은 제거했습니다. 학교생활에서 도움을 줄 수 있는 점·받고 싶은 점은 계속 입력합니다.

매칭된 두 회원이 각각 공유에 동의해야 서로의 휴대전화 번호를 볼 수 있습니다. 번호는 서버에서 AES-GCM으로 암호화해 별도 비공개 테이블에 저장하며 일반 커뮤니티 응답·관리자 명단에 포함하지 않습니다. 서버 암호화는 종단 간 암호화를 뜻하지 않습니다. 매칭 해제·계정 정지·삭제 시 공유 데이터를 정리합니다. 한쪽이 공유를 취소하면 상대의 다음 조회에서 번호가 사라집니다. 이미 상대가 복사한 번호까지 회수할 수는 없습니다.

## 공개·비공개 건의함

작성 시 공개 범위를 선택합니다. 공개 질문은 검토 후 모든 로그인 회원에게 표시하고, 비공개 질문은 작성자와 학생회 운영 담당자·학교 관리자만 확인합니다. 답변 작성은 학생회 임원(L3·L4)만 가능하며 L5도 학생회 답변을 작성하지 못합니다. 미승인 공개 질문과 답변은 별도 검토 목록에서 처리합니다.

## 학급 제출 현황

모든 로그인 회원이 각 학급의 제출 상태, 최초 제출자, 최근 수정자와 시각을 확인합니다. 제출 답변·수정 이력의 내용은 해당 학급 대표와 담당 운영진 권한을 유지합니다. 마감 후 기존 제출 건 수정은 차단하고 학생회 개인 채널로 연락하도록 안내합니다. 늦은 최초 제출 허용 여부는 업무 설정을 따릅니다.

## 운영 반영

SQL 001~016을 순서대로 적용하고 `account-access`, `moderate-post`를 배포합니다. 적용 이력에 있는 SQL은 다시 실행하지 않습니다. 멘토링 연락처 암호화는 기존 서버 전용 `TEMP_CREDENTIAL_KEY`를 사용하며 로그인 임시 비밀번호와 서로 다른 암호화 문맥으로 구분합니다.

로컬 가상 화면과 실제 Supabase에서 글 수정·원 작성 시각 보존·대댓글·하트·채널 접근 제한·상호 연락처 동의/취소·공개/비공개 건의·학생회 답변·제출 메타데이터 공개·답변 비공개·마감 차단을 검증했습니다. 원격 검증용 계정·글·신청·알림은 정리합니다.

## 참고

사용자가 지정한 [한국어 욕설 문서](https://namu.wiki/w/욕설/한국어)는 직접 접근이 되지 않아 [공개 미러](https://m.namu.moe/w/욕설/한국어)의 분류를 참고했습니다. 설명문이나 문서 전체를 복사하지 않고 학교용 규칙을 별도로 구성했습니다. [디시인사이드 게시판](https://gall.dcinside.com/board/lists/?id=programming)의 목록 구조를 확인했으며, 에펨코리아·네이버 카페는 서버 접근 제한이 있어 요청한 표형 목록·말머리·작성 시각이라는 공통 형식을 적용했습니다. 다른 사이트의 로고·이미지·스타일 코드는 복사하지 않았습니다.
